# Memory files and the MEMORY.md index

Read this before you archive, merge, rewrite or add a memory file or a `MEMORY.md` line. The index rides in every session; each memory file costs only when it is read.

## Index

- One line per memory: `- [Title](file.md) — when to read it`. A pointer, never the content.
- Use a few `##` sections so related lines sit together.
- When three or more memories belong to one kind of work, give them one small index file (`index-<topic>.md`) and link only that file from `MEMORY.md`.
- The report's unread lines (files never opened in the window) go first: archive them, or merge several into one line.
- A line whose file does not exist: delete the line or fix the path.

## Memory file

- One fact per file. File name: `<type>-<topic>.md`, lowercase with hyphens.
- Keep the frontmatter Claude Code already writes (`name`, `description`, type). Add nothing it does not use.
- `description`: one specific line saying what the file holds.
- For a correction or a rule: the rule, then **Why** and **How to apply**, so it can be judged later.

## Archive

- Move the file to an `archive/` folder next to it and drop its index line. Do not delete: it can come back.
- Archive when: never read in the report's window and not needed for upcoming work, a finished project, or a fact that is no longer true.
- Before archiving, check with the user; a memory can matter even if it is rarely read.

## After

Run the report again a week later: the unread-line finding should be gone or smaller.
